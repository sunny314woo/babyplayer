# BabyPlayer — Product Definition

> 当前状态：需求讨论阶段，尚未冻结。

## 1. 产品定位

BabyPlayer 是一个面向幼儿家庭的 Apple TV 本地媒体播放器。

它不是通用文件播放器，也不是家庭媒体服务器。

核心目标：

**让幼儿打开 Apple TV 后，通过简单、直观的大封面界面，找到喜欢的儿歌或儿童视频，并直接播放。**

理想操作路径：

**打开 App → 看到内容 → 点击封面 → 播放**

儿童不需要理解文件、目录、服务器、网络协议等概念。

---

## 2. 为什么做这个产品

现有播放器已经能够播放本地媒体，因此 BabyPlayer 的价值不是"能够播放视频"，而是提供更适合幼儿的使用方式。

### VLC

VLC 功能强大，但：

- 功能和入口较多；
- 文件管理属性明显；
- 操作方式偏工具化；
- UI 不适合幼儿；
- 幼儿很难独立找到自己想看的内容。

### Infuse

Infuse 的视觉设计和媒体库体验值得参考。

但它主要围绕电影、电视剧和成人家庭媒体库设计，并非围绕幼儿的认知和操作能力设计。

BabyPlayer 不试图成为另一个 Infuse。

可以借鉴的是：

**内容优先、大封面、打开即可浏览的媒体库体验。**

---

## 3. 产品哲学

### 3.1 内容优先

首页首先展示可以播放的内容，而不是文件夹、服务器或设置。

### 3.2 儿童优先

核心操作应简单到幼儿能够逐渐学会自己完成。

优先：

- 大封面；
- 少文字；
- 少层级；
- 少按钮；
- 明确的焦点和点击反馈。

### 3.3 隐藏技术细节

底层可以处理文件、媒体来源和元数据。

但儿童界面不应该让用户感觉自己正在操作"文件播放器"。

### 3.4 家长配置，儿童使用

复杂的低频操作由家长完成。

儿童日常界面保持简单。

### 3.5 严格控制范围

每增加一个功能，都必须先回答：

**它是否直接改善"找到内容 → 点击 → 播放"这条核心链路？**

如果不是，原则上推迟。

---

## 4. V1 核心闭环

V1 首先验证：

**家庭本地儿童媒体能否以比通用播放器更简单、更适合幼儿的方式，在 Apple TV 上浏览和播放。**

核心闭环：

**准备本地儿童媒体 → App 获取内容 → 首页展示 → 儿童选择 → 播放**

V1 的重点不是建立复杂的媒体管理系统，而是验证儿童实际使用体验。

---

## 5. V1 当前考虑的能力

### 5.1 内容首页

打开 App 后直接看到儿童内容。

以大封面作为主要视觉元素。

避免首先展示文件夹或复杂菜单。

首页结构：

- 顶部：固定三个分类选项卡（儿歌 / 动画 / 全部），切换后下方两行独立过滤
- 中间两行大封面 shelf（参考 Infuse 布局），两行对应两种**播放模式入口**：
  - 第一行：**白天模式**（正常观看场景）
  - 第二行：**哄睡模式**（哄睡 / 安抚场景）

家长在设置中把内容标记为"适合白天 / 适合哄睡 / 两者都适合"，系统据此填充两行。

每个内容项有一个播放适用性标签属性，取值为：

- `daytime`：只出现在白天模式行；
- `sleep`：只出现在哄睡模式行；
- `both`：同时出现在两行。

默认值为 `both`。Jellyfin 文件夹结构可用于提供初始分配；设置页提供家长手动调整的兜底入口。未分配或无法判断时按 `both` 处理，并在首页用温和提示引导家长前往设置。

从哪一行进入播放，就使用哪种播放模式。

封面：横版 16:9（视频原画面直接作为封面）。

V1 排序规则：默认排序 + 点赞/禁用标记（只记录，不做复杂计算）。

V2 补充智能排序：基于点赞率、退出行为的动态调整、记忆曲线推荐、按播放最少推荐。

### 5.2 内容组织

儿歌和动画归为同一类，通过播放列表区分。

选项卡固定为儿歌、动画、全部三个。儿歌和动画对应的 Jellyfin 媒体库或文件夹映射由家长配置，全部为两类内容的聚合视图。

### 5.3 播放

点击内容后直接进入播放。

播放界面保持简单，使用 tvOS 系统 AVPlayerViewController，针对 Apple TV 遥控器操作设计。

V1 提供两种播放模式：

**白天模式**（正常模式）：
- 每首视频循环 3 次（家长可在设置中调整）
- 循环次数达到后直接结束播放并回到首页
- V1 不自动播放下一首

**哄睡模式**（安抚模式）：
- 默认总播放时长为 30 分钟（家长可在设置中调整）
- 每首曲目只播放一次，不做单曲循环
- 达到设定时长或播放列表结束后退出播放，回到首页

播放中不显示剩余时间提示。

### 5.4 封面

优先读取媒体已有的可用封面。

没有可用封面时，由 Apple TV 端从视频画面截取生成默认封面。

### 5.5 本地媒体来源

V1 媒体文件存放在与 Apple TV 同一局域网的 Mac Mini（或其他电脑）上。

Apple TV 通过 **Jellyfin HTTP API** 访问媒体（方案 B）：
- 家长在 Mac Mini 上安装 Jellyfin，添加媒体文件夹（一次性操作）
- BabyPlayer 首次连接使用 **Jellyfin Quick Connect** 配对：
  - Apple TV 输入 Jellyfin 服务器 IP 后，屏幕显示 6 位数字码
  - 家长在 Mac Jellyfin 浏览器中点击批准
  - 配对成功后 Apple TV 永久记住，无需账号密码
- 之后打开 App 直接可用，无需重复配置

V1 不需要自建 Mac 配套端。

**媒体来源可扩展方向（V2 及以后）**

V2 及后续版本可根据实际需求选择媒体来源方案，不限于以下选项：

- 自建 Mac/iPhone 配套端：Bonjour 自动发现 + 数字码配对，零配置体验
- NAS：直接对接 Jellyfin on NAS，或支持 WebDAV/SMB（封装复杂度）
- 本地存储：USB 或外接硬盘直连 Apple TV
- 混合方案：多种来源并存

tvOS 端 UI 层与媒体来源解耦，后续切换或扩展来源时 UI 无需改动。

## 6. V1 明确不做

当前阶段不考虑：

- AI 推荐；
- AI 自动分类；
- AI 故事生成；
- 根据生活场景生成内容；
- 用户账号系统；
- 云同步；
- 社交功能；
- 在线儿童内容平台；
- 复杂媒体服务器；
- 多用户体系；
- 复杂推荐算法；
- 纯音频（MP3/AAC）；
- PIN 家长锁；
- 播放进度记录 / 继续播放。

不得因为"以后可能需要"而提前开发这些能力。

---

## 7. UI 与交互方向

整体借鉴 Infuse 的优点：

- 内容优先；
- 大封面；
- 清晰视觉层级；
- Apple TV 遥控器友好；
- 尽可能减少操作步骤。

但不复制成人电影媒体库设计。

BabyPlayer 应更加：

**简单、儿童化、直观。**

儿童化首先意味着儿童容易理解和操作，而不是增加大量卡通装饰、颜色或复杂动画。

UI 正式实现前，优先通过 Figma 确认主要页面和遥控器 Focus / 页面流转。

## 9. V1 成功标准

V1 成功不以功能数量衡量。

核心判断标准：

> 家长完成初始配置以后，幼儿是否能够打开 Apple TV App，看到自己熟悉的内容，通过封面找到它，并用极少操作开始播放。

如果能够做到这一点，V1 的核心产品假设即得到验证。
